# LIBERO auxiliary-label data contract

This is the training-time data contract for the four spatial branches described
in `SSI_WAM_LIBERO_Codex_Implementation.md`. Teacher inference remains offline;
the Fast-WAM dataset only reads precomputed caches.

## Source caches

Each cache is addressed by `(suite directory name, episode_index)`:

```text
depth_cache/<suite>/episode_XXXXXX.depth.npz
bbox_cache/<suite>/episode_XXXXXX.bbox.npz
motion_cache/<suite>/episode_XXXXXX.motion.npz
```

The current preprocessing schemas are:

| Cache | Arrays used by training |
|---|---|
| Depth | `frame_indices[L]`, `camera_keys[C]`, `depth[C,L,H,W]`, `depth_conf[C,L,H,W]` |
| BBox/Mask | `frame_indices[L]`, `bbox_xyxy[K,4]`, `bbox_confidences[K]`, `bbox_offsets[C,L+1]`, optional `bbox_masks[K,H,W]` |
| Trajectory | `frame_indices[L]`, `motion_points[C,L,N,2]`, `motion_visibility[C,L,N]`, `motion_point_source[C,N]` |

`bbox_masks[k]`, `bbox_xyxy[k]`, and `bbox_confidences[k]` describe the same
instance. Within a returned frame, instances are ordered by configured camera
order and then by cache order. The current cache text labels do not define a
stable class taxonomy, so `box_labels` is class zero (objectness-only, `C=1`).

## Time alignment

LeRobot provides the window start as `frame_index`. For a Fast-WAM sample the
raw frame timeline is:

```text
frame_index + arange(num_frames) * global_sample_stride
```

Episode-end padded positions are replaced with the last valid raw frame. The
same `video_sample_indices` used for RGB (default `0,4,...,32`) then select all
auxiliary targets. Every requested raw frame must occur exactly in each cache's
`frame_indices`; the loader raises an error instead of silently choosing a
neighboring label. Generate training caches with `--frame-stride 1` unless the
training sampler is explicitly aligned to a larger label stride.

The returned `aux_frame_indices[T]` records the exact raw timeline. With the
default LIBERO setup, `T=9` and the trajectory horizon is also 9.

## Spatial alignment and returned shapes

The loader composes cameras with the same `concat_multi_camera` setting as RGB,
then applies the same aspect-preserving resize and center crop to `video_size`.
For the default two-camera LIBERO configuration this maps two 224x224 views to
one 224x448 target without a crop.

| Field | Per-sample shape / type | Convention |
|---|---|---|
| `depth` | `[T,1,H,W]` float32 | cache values preserved (relative/inverse/metric) |
| `depth_confidence` | `[T,1,H,W]` float32 | `[0,1]` validity/confidence |
| `boxes` | `list[T]` of `[N_t,4]` float32 | normalized `cx,cy,w,h` |
| `box_labels` | `list[T]` of `[N_t]` int64 | zero = object |
| `box_scores` | `list[T]` of `[N_t]` float32 | teacher confidence |
| `box_camera_indices` | `list[T]` of `[N_t]` int64 | source camera index |
| `masks` | `list[T]` of `[N_t,H,W]` float32 | binary instance masks |
| `trajectories` | `[N,T,2]` float32 | normalized combined-canvas xy |
| `traj_visibility` | `[N,T]` float32 | invisible/out-of-crop = 0 |
| `traj_query_points` | `[N,2]` float32 | coordinate at window frame zero |
| `traj_point_source` | `[N]` int64 | `0=grid`, `1=random_dynamic` |
| `traj_camera_indices` | `[N]` int64 | source camera index |

All indexing and coordinate transforms happen in the Dataset layer. Models must
not apply a temporal offset or camera-coordinate correction.

This follows ATM's preprocessing convention: CoTracker xy coordinates are
divided by image width/height before storage, visibility is kept separately,
and the first trajectory frame acts as the query observation. ATM's
`TrackTransformer` consumes `[B,T,N,2]`; the future branch adapter should only
permute the collated `[B,N,T,2]` tensor and perform its configured point
selection (ATM samples tracks near a reference grid), not rescale coordinates.

## Batching

`RobotVideoDataset.collate_fn` is automatically installed when auxiliary labels
are enabled, and the trainer passes it to `DataLoader`.

- Dense fields are stacked normally.
- BBox/mask fields remain `list[batch][time]` because `N_t` is variable.
- Trajectories are padded to the largest point count in the batch and returned
  as `[B,N_max,T,2]`; `traj_point_is_pad[B,N_max]` marks padding.

## Configuration

The default remains disabled so baseline behavior is unchanged. Enable all four
data targets with:

```bash
python scripts/train.py --config-name train \
  data=libero_2cam model=fastwam task=libero_uncond_2cam224_1e-4 \
  data.train.auxiliary_labels.enabled=true
```

Individual data modalities can be disabled with, for example,
`data.train.auxiliary_labels.load_mask=false`. Mask loading requires bbox caches
generated by the `grounded_sam2` backend because only those contain
`bbox_masks`.

The LIBERO two-camera config selects views independently through
`camera_keys.depth`, `camera_keys.bbox`, `camera_keys.mask`, and
`camera_keys.trajectory`. All four default to
`observation.images.image` (agentview). A single-view target is returned as a
true 224x224 tensor, not a zero-filled 224x448 canvas. Set a modality to both
RGB keys to load its horizontal dual-view target. Matching per-branch model
settings select the same first-frame Video K/V camera regions; Action
attention continues to use both RGB views.

`cache_size` controls a small per-worker LRU independently for depth,
bbox/mask, and trajectory archives. The default retains one decompressed
episode per modality.

## Validation

When auxiliary branches are enabled, the trainer evaluates all four decoders
explicitly even though the model is in eval mode. It writes prediction/target
PNG pairs for depth, bbox, mask, and trajectory beside the existing
prediction/VAE/ground-truth MP4. W&B receives the total, video, action, and
per-auxiliary train/validation losses plus these validation media. Normal
action/video deployment still constructs no auxiliary tokens and performs no
auxiliary inference.

Check file coverage for every configured LIBERO episode and deeply inspect a
deterministic random subset with:

```bash
conda run -n fastwam python scripts/validate_libero_auxiliary_cache.py \
  --sample-count 12 --seed 42
```

The deep pass verifies exact depth/bbox/trajectory timeline equality, camera
order, full stride-1 coverage, finite tensors, ragged bbox offset integrity,
and one-to-one bbox/mask instance counts.
